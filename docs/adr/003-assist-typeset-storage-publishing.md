# 003. AI 에이전트·조판·파일 저장소·발행 경계

- 날짜: 2026-10-11
- 상태: 승인됨 (Raven이 이 작업 창에서 네 질문의 추천안을 선택)
- 관련 에픽: nn-gvs7
- 이전 결정: [ADR-002](002-spaces-identity-sessions.md)
- 범위: 설계만. 구현은 세 공간 분리 마일스톤이 develop에 병합된 뒤 새 마일스톤에서 한다.

## Context

작업실의 AI 편집자·어시스트, 파일 내보내기와 서점 발행에는 아직 도메인 계약이 없다. API에 TeX와 긴 실행을 모두 넣으면 요청 처리와 자원 사용이 서로 영향을 주고, 독자 화면이 편집 중 원고를 읽으면 발행 이후 수정이 공개본에 섞인다. ADR-002의 모듈형 모놀리스와 공개 스냅샷 경계를 확장한다.

에픽에서 이미 정한 제품 조건은 독자의 웹 읽기, 작가의 PDF·EPUB 생성, 연재 회차와 책 한 권의 발행이다. 유료 판매는 나머지 기능 이후에 붙이며 작업실 요금은 이 ADR의 범위 밖이다.

## Decision

### ADR-002와 권한·의존성

세 웹 공간, core-api 모듈형 모놀리스, 세션·역할 정책을 유지한다. 작업실의 assist·조판·파일 관리에는 `RequireSession`과 리소스 소유권 검사를 적용한다. author는 요구하지 않는다. 서점 발행·공개본 교체·회수에는 세션, 현재 author 자격, 작품 소유권과 필명 프로필을 요구한다. 상태 변경에는 ADR-002의 출처 검사를 유지한다. 독자의 무료 공개본 웹 읽기는 로그인 없이 가능하다. 유료 판매·구매 권한은 이번 설계에 포함하지 않는다.

ADR-002의 도메인 목록에 assist·typeset·assets를 추가하고 실행 진입점에 워커 두 개를 더한다. 기존 결정을 뒤집지는 않는다. 아래는 구현할 구조이며 현재 구현을 설명하는 ARCHITECTURE 본문은 바꾸지 않는다.

| 구성 | 책임·경계 | 예정 위치 |
|------|-----------|-----------|
| studio | 편집 중 원고·revision, 원고 읽기·제안 수락, 발행 입력 조립 | internal/studio |
| assist | 에이전트·대화·제안·실행·사용량 계약 | internal/assist |
| typeset | 내보내기 요청·불변 입력·조판 결과 계약 | internal/typeset |
| assets | 파일 소유권·메타데이터·준비 상태·접근 계약 | internal/assets |
| catalog | 공개 단위·스냅샷·노출 상태, 공개본만 조회 | internal/catalog |
| 플랫폼 어댑터 | Mongo 저장·큐, LLM 공급자, S3, 변환 도구 실행 | internal/platform 아래 각 어댑터 |
| assist-worker | 긴 AI 실행·취소·복구, TeX 없는 별도 이미지 | cmd/assist-worker |
| typeset-worker | 조판 실행·결과 저장, TeX 포함 별도 이미지 | cmd/typeset-worker |

표의 경로는 모두 `apps/core-api/` 아래다. HTTP 어댑터는 도메인 계약을 조합한다. assist·typeset은 studio의 읽기 계약과 assets의 제한된 계약에 의존하고, studio는 catalog의 발행 입력 계약에 의존한다. catalog는 studio·assist와 비공개 저장소에 의존하지 않는다. 저장소·LLM·변환 도구 구현은 도메인의 포트를 구현하며 도메인은 Echo·SDK·Mongo를 모른다. 공통 작업 임대 계약은 플랫폼 큐에 두고 업무별 입력·결과 검증은 각 도메인이 소유한다.

### assist 실행과 도구

assist는 core-api 안의 도메인이다. 짧은 대화는 API 프로세스가 실행하고, 작품 전체 분석 등 긴 작업은 같은 Go 모듈의 `cmd/assist-worker`가 실행한다. 경량 워커는 TeX를 포함하지 않으며 core-api와 같은 도메인 코드를 사용한다. 처음부터 별도 서비스·별도 API를 만들지는 않는다.

에이전트 정의는 목적, 프롬프트 버전, 공급자 기능 요구, 허용 도구, 실행 제한을 가진다. AI 편집자, 문법검사, 완급 분석, 이미지 기반 묘사는 이 정의와 도구 조합으로 확장한다. 도구는 사용자 소유의 작품·선택 영역·원고 버전·허용한 이미지 자산만 읽는다. 모델이 넘긴 사용자 ID나 경로로 접근 권한을 결정하지 않는다. 시스템이 사용자·작품 범위를 도구 실행에 주입하고 호출마다 검사한다.

assist가 사용하는 원고 읽기·제안 수락 계약은 studio가 소유한다. assist는 studio의 제한된 계약에 의존하며 Mongo 컬렉션을 직접 읽거나 쓰지 않는다. studio는 assist를 import하지 않고 HTTP 조립 계층이 수락 흐름을 연결한다. 원고와 이미지의 외부 공급자 전송은 실행 화면에서 사용자가 선택한 범위로 제한하며 동의·정책 안내는 assist 구현의 완료 조건이다. 원고 속 지시는 데이터로 취급하고, 모델에 임의 파일·네트워크·쉘·발행 도구를 주지 않는다.

공급자 추상화는 실행 입력, 스트림 이벤트, 구조화된 도구 호출, 사용량, 취소·오류를 감싸는 얇은 계약이다. 공급자마다 다른 기능은 capability로 드러내고 지원하지 않는 이미지·도구 호출을 조용히 흉내 내지 않는다. 공급자의 SDK 타입은 어댑터 안에 둔다. 에이전트 프롬프트·원고 도구·작업 상태는 특정 SDK에 의존하지 않는다.

공급자·모델·단가 버전·실행 제한은 서버 설정으로 고르며 브라우저는 공급자 비밀키를 받지 않는다. 최초 공급자와 SDK 버전은 구현 때 데이터 처리 조건·기능·비용을 확인해 선정한다. 이 ADR은 특정 공급자의 현재 가격이나 기능을 고정하지 않는다.

### 제안과 작가 수락

AI는 제안만 만들며 원고를 직접 수정하지 않는다. 제안에는 소유자, 작품·문서·선택 범위, 읽은 revision, 수정 전 내용의 해시, 제안문, 설명, 실행 ID를 기록한다. 작가가 수락할 때 studio가 소유권과 현재 revision을 다시 검사하고 조건부 갱신한다. 달라졌으면 충돌로 반환하여 재분석 또는 재선택하게 한다. 자동 덮어쓰기·자동 재기반은 하지 않는다.

원고 revision과 적용한 suggestion ID를 같은 원고 갱신에서 기록해 재요청이 같은 제안을 두 번 적용하지 않도록 한다. 별도 제안 기록의 accepted 상태는 이 적용 기록에서 복구할 수 있어야 한다. 모두 적용도 대상 문서의 한 revision에 대해 검증하며 겹치는 수정은 거절한다. 생성·수락·거절 기록은 분리하고 실행 재시도가 수락을 대신하지 않는다.

### 대화·실행·사용량

Mongo에 소유자·작품 범위가 있는 conversations, 별도 messages, assist_runs, suggestions를 저장한다. 대화 한 문서에 메시지를 끝없이 넣지 않는다. 메시지는 사용자 입력·완성 응답·도구 실행 요약으로 나누고 중단된 응답에는 partial 표시를 남긴다. 원고 참조는 문서 ID·revision·선택 범위·해시로 남기고, 실행에 필요한 불변 입력은 승인된 범위만 보관한다. 프롬프트 버전·모델·작업 상태는 재현·진단에 남기되 공급자의 비공개 추론 과정은 요구하거나 저장하지 않는다.

사용자가 대화·작업을 삭제하면 연결된 입력·제안·메시지·임시 파일도 삭제 대상으로 넘긴다. 사용량 장부는 원고·대화 본문 없이 별도로 보관하며 계정 삭제 시 사용자 식별자 처리와 보존 기간은 구현 시 개인정보 정책에서 정한다. 보존 기간이 정해지기 전 무기한 저장을 제품 기본값으로 만들지 않는다. 애플리케이션 로그에는 원고·프롬프트·세션·공급자 비밀키·서명 URL을 쓰지 않는다.

usage_entries는 사용자, run ID, attempt ID, provider call ID, 공급자·모델, 입력·출력·캐시 토큰 등 공급자가 보고한 단위, 통화, 단가 버전, 비용 값·출처(actual/estimated/unknown), 시각과 상태를 가진다. 비용은 통화와 정수 최소 단위 또는 고정 소수점으로 기록한다. 추정 단가와 공급자 청구액을 구분하고 사용자 판매 가격으로 취급하지 않는다. 동일 호출의 장부는 고유 키로 중복 반영을 막고 재시도에서 생긴 별도 호출은 모두 기록한다. 도구 루프의 각 호출도 포함한다.

외부 호출 전에 call intent를 영속 기록하고 완료·실패·취소 후에도 사용량을 확정한다. 공급자 응답 없이 연결이 끊기면 비용을 0으로 만들지 않고 unknown으로 남겨 공급자 조회가 가능하면 대조한다. 비용 발생 여부가 불명확한 호출은 자동 재전송하지 않는다. 사용자에게 재실행과 추가 비용 가능성을 알린 뒤 새 attempt로 실행한다. 큐 재전달이 이 규칙을 우회하지 못한다.

요금제·결제·월 한도를 정하지 않는다. 실행 승인 경계에 이용 자격·사용량 검사 포트를 남기고, 지금은 로그인·소유권과 운영상 동시 실행·입력 크기·최대 호출·시간 제한만 적용한다. 요청 수락과 실제 공급자 호출·워커 시작 시 검사하며 사용자별 usage 집계가 나중에 예약·한도 검사에 연결될 수 있게 한다. author 역할을 작업실 이용 자격으로 재사용하지 않는다.

### 스트리밍과 긴 AI 작업

작업실은 상태 변경 POST로 실행을 만들고 run ID를 받는다. 같은 출처의 별도 GET을 fetch로 읽는 SSE(`text/event-stream`)로 짧은 대화의 delta·도구 요약·상태·완료·오류를 받는다. 스트림 조회 자체가 새 실행을 만들지 않으며 사용자 세션·소유권을 검사한다. 이벤트에는 run ID·순번을 넣고 공급자 원문 이벤트 대신 서비스 계약을 노출한다. 원고 적용은 별도 수락 API로만 한다.

API 프로세스 안의 실행은 내구성 있는 run 기록을 먼저 만든 뒤 요청과 분리된 제한 시간의 실행 context로 돌린다. 브라우저 연결 종료는 관찰 종료이며 취소가 아니다. 명시 취소 요청이 provider context를 종료한다. 프로세스가 죽으면 만료된 실행을 interrupted로 회수하고 미확정 호출 사용량도 남긴다. 재접속은 run ID로 현재 상태·저장된 partial/최종 응답을 조회한다. 토큰 delta의 무손실 재생은 초기 계약에 포함하지 않으며 클라이언트는 저장 응답으로 화면을 맞춘다. 재접속이 모델 호출을 다시 시작하지 않는다.

nginx의 해당 스트림 경로는 `proxy_buffering off`, 캐시 비활성화와 충분한 읽기 timeout을 적용하고 API는 `X-Accel-Buffering: no`, `Cache-Control: no-store`와 주기적인 heartbeat를 보낸다. 끊긴 소비자·느린 소비자가 모델 실행을 무한히 붙잡지 않도록 이벤트 버퍼를 제한한다. 긴 분석은 HTTP 요청 수명과 분리하여 큐에 넣고 assist-worker가 처리한다. POST의 동일 멱등 키에는 동일 입력의 같은 run을 반환하고 다른 입력이면 충돌로 응답한다.

### 조판 입력·도구·워커

studio가 선택 범위와 원고 revision을 고정한 export snapshot을 조립한다. 구조(권·장·장면 순서), 제목·필명·언어, 표지·삽화의 준비된 asset ID, 판형·목차·문단 옵션, renderer/template/font 버전을 입력 manifest로 저장한다. 요청 뒤 원고가 바뀌어도 진행 중인 결과에는 섞이지 않는다. 개인정보 메모·대화·제안은 본문에 포함하지 않는다.

정규 입력은 UTF-8 제한 Markdown이다. 제목·단락·강조·인용·목록·구분선·서비스 자산 참조를 지원하고 임의 raw HTML·raw TeX·사용자 YAML·필터·파일 경로·외부 이미지 URL은 받지 않는다. 세부 문법과 한국어 조판 템플릿은 버전을 갖고 웹·EPUB·PDF의 지원 범위가 일치해야 한다.

| 결과 | 변환 경로 | 성격 |
|------|-----------|------|
| PDF | Markdown → Pandoc → 서버 LaTeX 템플릿 → XeLaTeX | 한글 글꼴 포함, 페이지·판형·쪽번호가 있는 조판본 |
| EPUB3 | 같은 Markdown·구조 → Pandoc EPUB3 writer | 재배치 본문·목차·메타데이터·이미지, PDF 레이아웃을 복제하지 않음 |
| LaTeX | PDF 경로의 생성 중간물 | 사용자 raw LaTeX 입력이나 LaTeX → EPUB의 무손실 왕복은 초기 범위 밖 |

작가에게 PDF·EPUB를 둘 다 생성하는 기능을 제공한다. 형식별 job과 상태를 분리해 PDF 실패가 EPUB 성공을 덮어쓰지 않게 한다. text·단일 HTML 내보내기는 기존 nn-6ldx의 후속 요구이며 같은 snapshot을 재사용한다. typeset은 assist 대화나 LLM을 호출하지 않는다.

`cmd/typeset-worker`는 같은 Go 모듈을 쓰되 Pandoc·고정 TeX Live 구성·XeLaTeX·한글 글꼴을 포함한 별도 이미지로 배포한다. core-api·assist-worker 이미지에는 이 도구들을 넣지 않는다. 도구·템플릿·폰트와 이미지 digest를 결과 메타데이터에 남긴다. 최초 템플릿은 XeLaTeX·한국어용 패키지와 Noto 한글 글꼴을 기준으로 검증하고, 판형·줄바꿈·문장부호·글꼴 임베드 품질은 구현 수용 검사에서 확인한다. 정확한 버전은 구현 때 고정하며 생성 시각 등 PDF 메타데이터 때문에 바이트까지 같다는 보장은 하지 않는다.

워커의 제어 프로세스만 Mongo·S3 자격을 가진다. 내려받아 검증한 입력·이미지만 작업별 임시 디렉터리에 놓고, 변환 자식 프로세스에는 자격 증명·DB·스토리지·외부 네트워크 접근을 주지 않는다. 비루트·읽기 전용 루트 파일시스템·전용 임시 공간과 CPU·메모리·디스크·프로세스 수·시간 제한을 적용한다. XeLaTeX는 shell escape를 끄며 서버가 소유한 템플릿만 쓴다. 명령은 인자 배열로 실행하고 사용자 문자열을 쉘 명령에 합치지 않는다. Pandoc sandbox만으로 PDF 격리가 완성된다고 보지 않는다.

### Mongo 작업 큐와 실패 복구

초기에는 별도 Redis·메시지 브로커 대신 Mongo의 jobs를 폴링한다. `kind`로 assist/typeset을 분리하고 각 워커는 자기 종류만 선점한다. job은 소유자, 불변 입력 참조·해시, 상태, attempt, availableAt, leaseOwner·leaseToken·leaseUntil, 취소 요청, 결과 참조와 오류 분류를 가진다. 입력 본문·파일은 job에 넣지 않는다. 관련 인덱스는 `(kind, status, availableAt)`, `(kind, status, leaseUntil)` 및 소유자별 멱등 키 unique다. 작업별 입력 크기는 Mongo 문서 한도보다 작은 서비스 상한으로 검증한다.

흐름은 `queued → running → succeeded/failed/canceled`다. 재시도할 수 있는 실패와 임대 만료는 availableAt에 지수 backoff를 넣어 queued로 돌리며 attempt 상한을 넘으면 failed다. 취소 요청이 있는 queued job은 canceled로, running job은 변환·공급자 실행을 중단하고 canceled로 간다. 완료와 취소의 경쟁은 현재 lease·상태·취소 플래그를 포함한 조건부 갱신으로 결정한다. 이미 succeeded면 취소로 결과를 소급 폐기하지 않는다.

선점은 `findOneAndUpdate`의 조건부 단일 문서 갱신으로 lease와 증가한 attempt/token을 함께 부여한다. heartbeat·완료·재시도·취소 확정에도 같은 token과 유효 임대를 요구한다. 임대가 만료된 옛 워커는 새 워커의 결과를 덮어쓸 수 없다. 시간 기준은 DB 시간을 사용한다. 이 큐는 at-least-once이며 exactly-once 실행을 약속하지 않는다. typeset은 재생성 가능한 입력으로 재실행하고, assist는 저장한 checkpoint와 call intent를 읽어 확정 호출은 재사용·불명확 호출은 interrupted로 넘긴다.

결과 파일은 attempt별 새 키에 업로드하고 검증 후 결과 목록을 job 완료 갱신에 붙인다. 성공 lease의 결과만 업무 기록에 멱등 반영한다. 업로드 뒤 DB 갱신 전에 죽었거나 임대를 잃은 attempt의 파일은 고아 파일 수거 대상이며 사용자가 접근할 수 없다. job 완료 후 업무 기록 반영 전에 죽으면 조정 작업이 완료 job을 읽어 복구한다. 입력 manifest가 준비되기 전에 queued job을 만들지 않으며, 생성 실패로 남은 입력도 수거한다. Mongo·객체 저장소 사이의 트랜잭션이나 정확히 한 번의 외부 호출을 가정하지 않는다.

큐 지연·임대 만료·실패/재시도·unknown 비용을 관측하고 사용자별 동시 작업 수를 제한한다. 큐 부하가 Mongo 요청 처리에 영향을 주거나 지연·라우팅·독립 확장 요구가 커지면 이 job 계약을 유지하고 브로커를 재검토한다.

### 파일 저장소와 접근

운영은 AWS S3, 개발은 MinIO를 쓰는 S3 호환 ObjectStore 포트를 둔다. API는 객체 bytes를 Mongo에 넣지 않는다. Mongo의 assets에는 소유자, 용도(표지·삽화·export·publication), storage key, MIME·크기·SHA-256, 준비 상태, 원본/파생 관계와 생성 버전을 둔다. URL은 저장하지 않고 필요할 때 발급한다. 원고·대화 입력, 작가 export와 공개본 저장 공간·자격을 분리하고 모든 버킷은 비공개로 둔다. 서점 경로는 비공개 자산을 읽는 포트를 주입받지 않는다.

업로드는 권한 확인 후 서버가 새 키의 임시 업로드를 할당하고 짧은 서명 URL/POST 정책을 발급한다. 키를 사용자가 지정하게 하지 않는다. 업로드한 임시 객체를 MIME·크기·해시·이미지 디코딩으로 검사하고, 변환·재인코딩한 별도 ready 키에 저장한 뒤 자산으로 확정한다. 서명 URL을 다시 써도 ready 객체를 교체할 수 없다. SVG·임의 HTML·사용자 PDF/EPUB 업로드를 초기 이미지 입력으로 받지 않는다. 확정 API 재호출은 멱등이며 만료·실패 업로드는 수거한다.

작업실 다운로드는 현재 사용자·소유권·ready 상태를 확인한 뒤 기본 5분 GET 서명 URL을 발급한다. 업로드 URL은 기본 10분이며 크기 제한은 서명 정책과 확정 검사에서 검증한다. SDK 서명과 실제 브라우저 endpoint·CORS 설정을 개발 MinIO와 S3 각각에서 검사한다. 서명 URL은 만료 전 재사용 가능한 bearer 접근권이므로 로그·대화·공개본에 넣지 않는다. 발급 후 사용자 로그아웃·권한 변경이 이미 발급된 URL을 즉시 회수하지는 못한다.

파일 결과는 작가가 삭제하거나 연결된 작품을 삭제하기 전까지 보관하는 사용자 자산이다. 공개 snapshot에서 참조 중인 자산은 원고·작가 export 삭제와 무관하게 유지한다. 임시 입력·실패 attempt·고아 객체는 유예 기간 뒤 수거하고, GC는 준비 중 작업과 공개본 참조를 다시 확인한 후 삭제한다. 큐·자산 tombstone과 재시도 가능한 삭제 작업으로 Mongo와 S3의 불일치를 복구한다. 공개본 회수는 노출 중단이며 물리 삭제와 구분한다. 보존·삭제 기간, 백업 복구·영구 삭제 기준은 구현 운영 정책에서 구체화한다.

MinIO 공개 저장소는 확인일에 보관 상태이고 커뮤니티 배포는 소스 중심이다. 개발 이미지의 소스 revision·빌드 방법·digest를 고정하고 검증한다. 유지보수되는 개발 대체품이 필요하면 S3 포트는 유지하고 개발 공급자만 재검토한다. 운영 AWS S3 선택은 개발 MinIO 이미지에 의존하지 않는다.

### 연재 회차와 책의 판

catalog의 work는 서점 작품 식별자·공개 메타데이터다. publication unit은 `episode` 또는 `edition`이며 작품마다 둘 다 둘 수 있다. episode는 안정된 회차 ID·표시 순서·제목, edition은 안정된 책 ID·판 표시와 선택한 장·회차의 고정 순서를 가진다. 책은 기존 공개 회차 묶음 또는 비공개 원고에서 만들 수 있고 특정 회차의 최신본을 동적으로 따라가지 않는다.

각 unit의 release(snapshot)는 별도 불변 ID, 공개 본문·목차·표지·삽화 manifest, 원본 revision 목록·내용 해시, 필명/제목/언어, renderer 버전, 선택 결과물 참조를 가진다. 동일 책의 내용·구성·필명 등 변경은 새 release로 발행한다. episode 수정도 이전 본문을 덮어쓰지 않고 새 release를 선택한다. unit의 노출 상태와 activeReleaseId만 바꾸며 기존 release는 작업실 발행 이력에 남긴다. 책의 새로운 판과 같은 판의 정정은 각각 edition ID와 release ID로 구분한다.

발행 입력은 studio가 소유권·author·필명과 원고 revision을 검사해 조립하는 값이다. catalog에는 공개할 본문·메타데이터·공개용 자산 참조만 넘긴다. private 원고 ID는 추적 메타데이터일 뿐 catalog가 원고를 조회할 권한이나 경로로 쓰지 않는다. AI 대화·제안·메모·원고 저장소 키를 public DTO에 넣지 않는다.

### 공개 스냅샷과 웹·파일 결과

1. studio가 사용자가 고른 revision·순서로 발행 입력과 콘텐츠 해시를 고정한다. 이후 원고 편집은 별개다.
2. 공개할 이미지는 검증된 자산에서 공개본 소유의 별도 immutable key로 복사하고 웹 본문은 제한 Markdown에서 allowlist로 정제한 HTML로 만든다. 태그·속성·URL 스킴을 제한하고 script·이벤트 핸들러·iframe·raw HTML을 허용하지 않는다. 이미지 주소는 만료 URL 대신 공개본 asset ID다.
3. 정제 HTML은 장/회차별 객체로 저장하고 목차·해시·asset ID를 포함한 불변 manifest를 준비한다. 책 전체를 하나의 Mongo 문서에 넣지 않는다. 크기·구조·참조와 결과 준비를 검증한 뒤 catalog에 ready release를 등록한다.
4. 마지막으로 publication unit 한 문서의 상태·activeReleaseId를 예상 버전으로 조건부 갱신한다. 이 갱신이 공개 시점이다. 다른 발행과 경합하면 충돌을 반환한다. 같은 멱등 키는 같은 release를 반환한다. 포인터 교체 전 실패는 현재 공개본을 바꾸지 않으며 고아 준비물은 수거한다.

unit 공개 상태와 activeReleaseId가 독자 조회의 유일한 기준이다. reader는 이 포인터로 도달하는 ready 공개본의 HTML·이미지만 서비스 API를 통해 읽으며 private 키나 미선택 release에는 접근하지 못한다. catalog가 소유한 공개 저장소 포트에서만 읽고 웹 응답에는 필명·공개 DTO만 반환한다. 초기 웹 본문·이미지는 이 API를 거쳐 제공해 회수 후 새 읽기를 차단하며, 공개 HTML·이미지 응답은 `Cache-Control: no-store`로 한다. 이미 독자가 받은 내용 자체를 회수할 수는 없다. CDN·공유 캐시를 넣을 때에는 회수 전파 정책을 별도로 설계한다.

PDF·EPUB는 이 release의 원본 Markdown·순서·메타데이터·공개 자산 manifest로 typeset에 요청한다. 웹 HTML을 PDF로 인쇄하거나 EPUB에서 웹 본문을 추출하지 않는다. 파일 생성 실패·재시도가 activeReleaseId와 웹 본문을 바꾸지 않는다. 원문 manifest는 공개용 저장 공간 안에 있어도 독자에게 노출하지 않는다. 결과물은 release ID·입력 해시·도구 버전에 연결된 별도 artifact 기록에 추가하며 불변 본문 manifest를 수정하지 않는다. 동일 입력 결과물의 교체도 새 artifact ID로 남긴다.

독자에게는 우선 웹 읽기만 제공한다. 작가의 PDF·EPUB 생성·다운로드 권한이 독자의 다운로드 권한으로 전파되지 않는다. 나중에 독자 파일 제공을 도입하면 공개본 단위의 허용·이용 자격 계약을 더하되, 지금 서점에는 파일 다운로드 경로를 만들지 않는다. author가 아닌 사용자의 작업실 export는 발행 없이 가능하다.

회수는 unit을 withdrawn으로 조건부 갱신하여 이후 웹 조회를 차단한다. public DTO 조회와 본문/이미지 조회 모두 노출 상태를 검사한다. 이전 release·작가 export는 작가의 소유권 검사 아래 남긴다. 재발행·정정은 현재 author·소유권·필명과 같은 공개 준비 계약을 다시 거친다. moderation에 의한 차단은 author 자격과 독립된 노출 차단 포트를 사용하며 실제 심사 정책은 후속 범위다.

## Alternatives

- assist를 처음부터 별도 서비스로 분리하면 API 부하를 격리할 수 있으나 권한·원고 계약과 운영이 중복된다. 도메인을 공유하는 경량 워커로 긴 실행만 분리하고 독립 배포 필요 시 재검토한다.
- AI 직접 수정은 빠르지만 revision 충돌과 의도하지 않은 원고 변경이 생긴다. 제안 후 작가 수락을 선택한다.
- 공급자 기능 전체를 공통화하는 큰 프레임워크는 시작 비용과 제약이 크다. 얇은 포트와 capability 검사로 시작한다.
- API 이미지에 TeX 포함, HTML → Chromium PDF, Typst PDF, 직접 EPUB 생성도 가능하다. 이번에는 API 이미지와 변환 부하를 분리하고 Markdown에서 LaTeX·EPUB를 만드는 Pandoc·XeLaTeX를 선택한다. 한국어 조판 수용 검사에서 품질이 맞지 않으면 변환 어댑터를 재검토한다.
- Redis·전용 브로커는 큐 운영 기능이 풍부하지만 초기에는 Mongo 임대·조건부 갱신과 복구로 시작한다.
- 원고를 서점이 바로 읽거나 PDF/EPUB를 웹 읽기의 원본으로 삼으면 발행 경계와 웹 접근성이 약해진다. 별도 공개 스냅샷·정제 HTML을 선택한다.
- 운영 MinIO 대신 AWS S3를 선택해 저장소 운영을 맡긴다. 개발도 S3를 쓰는 대안은 비용·외부 계정 의존이 있어 MinIO로 시작한다.

## Consequences

작가가 원고를 고쳐도 공개본·진행 중 조판·AI 분석 입력은 유지된다. 작가는 author 신청 전에도 AI와 PDF·EPUB를 사용할 수 있고 발행할 때만 자격·필명이 필요하다. 웹 공개가 조판 완료나 공급자 상태에 종속되지 않는다.

워커 두 개, 객체 저장소, 작업·사용량 장부와 스냅샷 복구·GC를 운영해야 한다. Mongo 큐는 중복 실행·미확정 외부 비용·고아 객체를 복구하는 책임을 애플리케이션에 남긴다. 조판은 격리와 한글 품질 검증이 필요하며 S3·MinIO의 동작 차이를 계약 테스트로 확인해야 한다.

구현 수용 검사는 원고 소유권·author 경계, 제안 수락의 revision 충돌·중복 방지, 실제 nginx를 통한 첫 delta 도착·끊김/재접속, 워커 종료·임대 만료·옛 token 완료 거절, 미확정 공급자 호출 비용, 업로드 재사용·검증·파일 준비 실패, 공개 포인터 경합·회수, 원고 수정/삭제 후 공개본 유지, PDF 한글 글꼴·판형·줄바꿈과 EPUB3 검증을 포함한다. 이 ADR에서는 코드를 작성하거나 이 동작을 구현했다고 표시하지 않는다.

재검토 조건은 공급자 고유 실행 모델을 얇은 계약으로 표현하기 어려워지는 때, AI 도메인 독립 운영 필요, Mongo 큐 병목, 한국어 조판 품질 부족, 개발 MinIO 유지보수 불가, 독자 파일 제공·유료 판매, 공개 CDN 도입 또는 보존 정책 변경이다.

## 기술 근거

확인일: 2026-10-11. 제품 선택은 이 창의 사용자 답이고 아래 자료는 도구·운영 계약의 근거다.

- [Pandoc 사용자 가이드](https://pandoc.org/MANUAL.html): PDF 엔진·LaTeX·EPUB 지원, raw 입력과 sandbox의 범위. sandbox는 필터·PDF 생성을 격리하지 않는다.
- [Pandoc EPUB 안내](https://pandoc.org/epub.html): EPUB3 writer와 메타데이터·목차·이미지 지원.
- [XeTeX 참조](https://texdoc.org/serve/xelatex/0): shell escape 비활성화 등 엔진 실행 옵션.
- [Mongo 원자적 갱신](https://www.mongodb.com/docs/manual/core/write-operations-atomicity/): 단일 문서 원자성·현재 값 조건으로 경쟁 갱신 방지. 여러 문서 쓰기는 함께 원자적이지 않다.
- [Mongo 문서 한도](https://www.mongodb.com/docs/manual/core/document/#document-size-limit): BSON 문서 최대 16 MiB. 책·메시지·job 본문을 끝없이 한 문서에 넣지 않는 이유다.
- [nginx proxy 문서](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_buffering): 응답 버퍼링과 X-Accel-Buffering 제어.
- [S3 서명 URL](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html): 임시 접근·만료·재사용·동일 키 업로드 교체 동작.
- [MinIO 공식 저장소](https://github.com/minio/minio): S3 호환, 공개 저장소 보관 상태와 소스 배포. 개발 이미지 재현·유지보수 조건을 구현 전에 확인한다.
